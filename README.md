# AI-ANA — подбор подрядчиков для событий

Сервис помогает выбрать до трёх event-подрядчиков в Казахстане по городу, дате, формату, категории и бюджету. Каждая карточка объясняет выбор фактами профиля; основания можно раскрыть. Пустая выдача показывает причины, а смена даты — влияние календаря.

Приложение работает на **66 профилях предоставленного CSV**. Реализованы сайт, API, строгий импорт CSV/JSONL, детерминированный подбор и объяснения, регистрация, вход и личный профиль. Внешняя AI-модель не вызывается, ключи и платные сервисы для запуска не нужны. Бронирование, заявки, оплата и поиск подрядчиков в интернете в проект не входят.

## Быстрый запуск

### Через Docker

При установленном Docker Engine/Desktop и Docker Compose из корня проекта:

```bash
docker compose up --build -d --wait
```

Сайт: **http://localhost:8080**, API: http://localhost:8080/docs. Сервисы `frontend` (Nginx) и `backend` (FastAPI) запускаются вместе; Python и Node на компьютере не нужны. Аккаунты сохраняются в Docker volume `auth-data`. Локальная база из `data/auth/` автоматически в контейнеры не переносится; безопасный перенос описан в [инструкции Docker](docs/docker.md).

```bash
docker compose ps
docker compose logs --tail=100
docker compose down
```

Обычный `down` сохраняет аккаунты; не добавляйте `--volumes`/`-v`, если хотите сохранить их. Настройки порта и адреса сайта — в корневом `.env.example`. [Сборка, проверка, перенос базы и публикация](docs/docker.md).

### Без Docker

Проверенная среда: **Linux, Python 3.13.5, Node.js 20.19.2, npm 9.2.0**. Нужны Python с модулем venv, Node/npm и доступ к пакетным реестрам для первой установки. Версии зависимостей закреплены в `backend/requirements.txt` и `frontend/package-lock.json`. Vite требует Node ^20.19.0 или >=22.12.0; сервер — Python >=3.13. Нативный Windows не проверялся; Python-набор включает uvloop.

Все команды ниже начинаются из корня проекта, если не указано иное.

### 1. Установка

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
cd frontend
npm ci
cd ..
```

### 2. Сервер — первый терминал

```bash
backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Сервер полностью читает каталог при старте. Проверка готовности: http://localhost:8000/health. Ожидается `status: ready`, `profile_count: 66` и версия каталога. Описание API: http://localhost:8000/docs.

### 3. Сайт — второй терминал

```bash
cd frontend
npm run dev -- --port 5173 --strictPort
```

Откройте **http://localhost:5173**. Нажмите «Подобрать подрядчиков»: исходные параметры дают Куррапику, Мицури Канроджи и Кики. После смены даты на 01.10.2026 и повторной отправки остаются две карточки — Кики занят по календарю.

Сервер и сайт должны работать одновременно. Остановка каждого процесса — Ctrl+C. Если порт занят, остановите свой прежний процесс или задайте другой порт; `--strictPort` не позволяет незаметно сменить адрес.

### Собранная версия

При работающем сервере, из `frontend/`:

```bash
npm run build
npm run preview -- --port 4173 --strictPort
```

Адрес: http://localhost:4173. И dev, и preview проксируют `/api` на FastAPI. Браузеру не требуется отдельная настройка CORS. Для публичного размещения потребуется настроить тот же маршрут `/api` через reverse proxy; развёртывание не выполнялось.

Нажмите «Войти» в шапке → «Регистрация», укажите имя, email и пароль от 15 до 128 символов. Город необязателен. После регистрации откроется профиль: можно изменить имя и город, сохранить изменения и выйти. Email используется для входа и в этой версии не редактируется. ## Данные и ограничения

Основной источник — `hackathon dataset anonymized .csv` из корня. HTML служит справочным превью, DOCX — материалом задания; приложение не извлекает из них профили. CSV, HTML, DOCX и пользовательский JPEG не изменялись. Производный `data/derived/catalog.jsonl` содержит тот же набор и не загружается одновременно с CSV.

| Поля профиля | Смысл |
|---|---|
| `id`, `anon_name` | Стабильный идентификатор и анонимизированное имя |
| `categories`, `city`, `event_formats`, `languages` | Категории, город, форматы и языки работы |
| `price_from_kzt` | Начальная цена за мероприятие в целых тенге |
| `max_hours` | Максимальная длительность либо null |
| `busy_dates` | Занятые календарные даты |
| `description` | Полное исходное описание |
| `synthetic`, `city_imputed`, `price_imputed` | Синтетический профиль, дополненные город и цена |

В CSV списки разделены `|`, флаги — `True`/`False`, пустая ячейка `max_hours` означает null. Все 13 полей обязательны; отсутствие поля не заменяется пустым значением. Некорректный каталог не загружается частично. Подробные правила и диагностика: [catalog.md](docs/catalog.md).

Исходный набор: 50 профилей в Алматы, 15 в Астане, 1 в «Зарубежье»; 17 категорий. В нём уже были 13 синтетических профилей, 8 дополненных городов, 18 дополненных цен и 9 null-длительностей. Команда не добавляла профили в основной каталог. Тестовые фикстуры хранятся отдельно.

- Календарь: **23.09.2026–31.12.2026 включительно**. Дата за пределами — ошибка ввода.
- Цена «от» не является окончательной стоимостью заказа.
- Доступность известна только по календарю набора, без подтверждения подрядчиком.
- `max_hours: null` означает, что услуга не привязана к длительности присутствия; фильтр часов не применяется. Это не обещание неограниченной работы.
- Происхождение `original`, `team`, `demo` хранится отдельно от `synthetic`. Исходный синтетический профиль не выдаётся за добавленный командой или проверенный коммерческий профиль.

## Как работает подбор

Запрос → проверка полей и справочников → группа города и категории → обязательные условия → стабильный порядок → до трёх карточек → объяснения и причины исключения.

Профиль проходит только при свободной дате, поддерживаемом формате и начальной цене не выше бюджета. Указанные язык и длительность также обязательны; часы сравниваются только при `max_hours`, не равном null. Все прошедшие сортируются по `(price_from_kzt, normalize_key(id))`, затем берутся первые три. `normalize_key` применяет Unicode NFKC, свёртку пробелов и casefold. Рейтинг качества не вычисляется; флаги происхождения и дополнения данных порядок не меняют.

При нескольких нарушениях сохраняются все причины. В общий счётчик профиль попадает один раз: занятость → формат → бюджет → язык → длительность. Благодаря этому количество исключений сходится с размером группы. [Точные правила](docs/matching.md).

| Исход | Значение |
|---|---|
| `MATCHED` | Подходит хотя бы один профиль, показаны до трёх |
| `CATEGORY_UNAVAILABLE` | В выбранном городе нет категории из общего справочника |
| `NO_MATCHES` | Категория есть, но все профили исключены по условиям |

Ошибки ввода и технические сбои — отдельные состояния, не пустой подбор. При новом запросе старые карточки сразу убираются, прежний запрос отменяется, запоздалый ответ игнорируется. Если поля изменены без отправки, предыдущая выдача явно подписана. Сравнение дат использует диагностику сервера: занятость отличается от выхода подходящего профиля за первые три.

## Объяснения и роль AI

Объяснение соединяет условия запроса с отличительным фактом описания. Для исходного каталога вручную размечены 61 точный фрагмент и 5 недостаточно содержательных описаний. Исходные описания сохранены; отображаемый текст очищается от декоративных символов. Раскрываемые «Основания» позволяют проверить утверждения. Хэш описания и контекст полей защищают от применения устаревшей разметки.

При неизвестном или изменённом профиле остаются структурированные факты и честное предупреждение об ограничении объяснения. Минимальные сроки и противоречия описания показываются предупреждениями, не заменяя согласованные фильтры. [Контракт и правила объяснений](docs/api.md).

**NVIDIA API предусмотрен как необязательное улучшение, но не реализован и не проверен.** Внешние модели не вызываются; текущие объяснения формируются программно из разметки и данных. Предусмотренные ТЗ имена настроек приведены ниже. В текущем приложении они **не используются**, заполнение не включает интеграцию; адрес и поддержку модели потребуется перепроверить перед отдельным этапом. Пустой model id намеренно не заменён выдуманным.

```dotenv
AI_PROVIDER=none
NVIDIA_API_KEY=
NVIDIA_BASE_URL=https://integrate.api.nvidia.com/v1
NVIDIA_MODEL=
NVIDIA_REQUEST_TIMEOUT_SECONDS=15
NVIDIA_MAX_RETRIES=1
```

Автоматических советов по ослаблению условий тоже нет: параметры меняет пользователь.

## API и команды каталога

Пример запроса к работающему серверу, из корня:

```bash
curl -X POST http://localhost:8000/api/recommendations \
  -H 'Content-Type: application/json' \
  --data-binary @docs/queries/corporate-host.json
```

API: `GET /health`, `GET /api/catalog/meta`, `POST /api/recommendations`. Бизнес-исходы возвращают 200; ошибка запроса — 422; каталог недоступен — 503; внутренний сбой — 500. У ошибок единая структура `code`, `message`, `issues`. [OpenAPI](docs/openapi.json) и [сохранённые ответы](docs/api-examples/).

Из `backend/`:

```bash
.venv/bin/python -m app.cli
.venv/bin/python -m app.match_cli --query docs/queries/corporate-host.json
.venv/bin/python -m app.cli --export data/derived/new-catalog.jsonl
.venv/bin/python -m app.cli data/derived/new-catalog.jsonl
```

Относительные пути CLI отсчитываются от корня проекта. Экспорт создаёт JSONL и `.meta.json` с происхождением; переносите их вместе. Существующие файлы не перезаписываются — при повторе выберите новое имя. Изменение данных требует перезапуска сервера.

### Конфигурация

| Переменная | Где используется | По умолчанию |
|---|---|---|
| `CATALOG_PATH` | FastAPI: путь относительно корня или абсолютный | Исходный CSV |
| `CATALOG_ORIGIN` | FastAPI: original / team / demo; должен согласовываться с sidecar | original, если sidecar отсутствует |
| `API_PROXY_TARGET` | Процесс Vite dev/preview: адрес FastAPI | http://127.0.0.1:8000 |

Переменные задаются в окружении процесса; отдельный `.env` не нужен. Для готового JSONL из корня:

```bash
CATALOG_PATH=data/derived/catalog.jsonl backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

### Отдельный демонстрационный каталог

Исходный CSV уже есть, поэтому демофикстура не требуется для основного показа. Для проверки отдельного режима остановите прежний dev-сервер и запустите из корня:

```bash
CATALOG_PATH=backend/tests/fixtures/catalog_valid.jsonl CATALOG_ORIGIN=demo backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8001
```

В другом терминале, из `frontend/`:

```bash
API_PROXY_TARGET=http://127.0.0.1:8001 npm run dev -- --port 5173 --strictPort
```

Появится постоянный баннер «Демонстрационные синтетические данные». Фикстура содержит два вымышленных профиля для проверки импорта, не полный набор демонстрационных сценариев. Она не смешивается с исходными 66 профилями. Дополнения команды аналогично подключаются отдельным источником с `CATALOG_ORIGIN=team` и `synthetic: true`.

## Оформление и бренд

«Оформление» в шапке: четыре пресета, собственный HEX, палитра и сброс. В браузере сохраняется только акцент (`ai-ana-accent` в localStorage); форма и выдача после перезагрузки не восстанавливаются. Изменение цвета без перезагрузки сохраняет поля, карточки и раскрытые основания и не вызывает API. При недоступном хранилище цвет действует до перезагрузки.

Логотип — копия пользовательского JPEG, он не перекрашивается. Favicon — временная монограмма. Для замены положите файлы в `frontend/public/brand/` и обновите `logo`, `favicon`, `alt` в `frontend/src/config/brand.ts`, затем пересоберите сайт и обновите страницу. Размеры сохраняются CSS; исходный JPEG не перезаписывайте. [Принятые решения и подробная инструкция](docs/design.md).

## Проверки и скорость

Для проверки сервера, из `backend/`:

```bash
.venv/bin/python -m pytest -q
```

Для браузера, из `frontend/`:

```bash
npx playwright install chromium
npm run test:stage7
```

На Linux могут потребоваться системные библиотеки Chromium: `npx playwright install-deps chromium` требует прав установки системных пакетов. Полный браузерный прогон сначала собирает сайт, затем сам запускает отдельные FastAPI на 8002 и Vite preview на 4174, после проверки останавливает их. Порты должны быть свободны. `npm run test:e2e` использует dev-сервер на 5174 и пропускает production-замеры.

Итог этапа 7: **247 серверных и 15 браузерных проверок прошли**, сборка успешна. Проверены исходные сценарии, границы условий, ошибки, детерминизм после перестановок и перезапуска, доказательства, смена даты, оформление и ширины 1440/768/390/320 px. Один прежний warning Starlette/httpx и предупреждения NO_COLOR/FORCE_COLOR не привели к ошибкам. Тесты запускались после завершения этапа.

Пять повторов в локальном production Chromium: отправка формы → готовая выдача в среднем **49.84 мс**, медиана 48.8 мс, максимум 52.7 мс. Среднее fetch→JSON — 10.56 мс. Linux, Ryzen 7 5700U, один worker, локальный proxy и 66 профилей; без параллельной нагрузки. Начальная загрузка страницы и ввод параметров не включены. Это малая локальная выборка, не обещание времени на внешнем сервере.

## Ограничения и статус

Обязательное ядро реализовано; сведения об этапах и фактическом повторе запуска — в [progress.md](docs/progress.md) и [handoff.md](docs/handoff.md). Отсутствия исходных данных, необходимых для основного сценария, нет.

Не проверялись публичный хостинг, WAN-задержки, параллельная нагрузка, Firefox/WebKit, физические телефоны и экранные дикторы. Не измерялась полная загрузка страницы. Не заявляются подтверждённое качество подрядчиков, коммерческий эффект или готовность к большому каталогу. NVIDIA, бронирование и автоматические советы не реализованы. Дополнительные функции не включаются без отдельного согласования.
