# AI-ANA — подбор подрядчиков для событий

Сервис для выбора до трёх event-подрядчиков в Казахстане с понятными объяснениями. Выполнены этапы 1–5: визуальный прототип, загрузка каталога, подбор, объяснения с доказательствами и API. Сервер читает 66 исходных профилей из CSV, поддерживает JSONL и сохраняет происхождение записей. Подбор работает через Python, CLI и POST /api/recommendations. Фронтенд пока не подключён к API: карточки сайта остаются явно вымышленными демонстрационными данными. NVIDIA API не подключён.

## Локальный запуск

Проверенная среда: Node.js 20.19.2, npm 9.2.0. Зависимости закреплены в `frontend/package-lock.json`.

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Если порт занят, Vite сообщит другой адрес в терминале.

```bash
npm run build
npm run preview
```

Предпросмотр сборки: http://localhost:4173. Для остановки сервера нажмите Ctrl+C.

## Проверка интерфейса

```bash
cd frontend
npx playwright install chromium
npm run test:e2e
```

На Linux для Chromium могут понадобиться системные библиотеки: `npx playwright install-deps chromium` (установка системных пакетов требует соответствующих прав). Тесты сами запускают Vite на порту 5173. Проверяются четыре ширины, форма, состояния и оформление; снимки записываются в `docs/screenshots/`.

## Сервер и каталог

Проверенная среда сервера: Linux, Python 3.13.5. Точные версии всех установленных зависимостей закреплены в `backend/requirements.txt`. Из корня репозитория:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Адреса:

- http://localhost:8000/health — готовность каталога, число записей и версия.
- http://localhost:8000/api/catalog/meta — справочники, окно календаря, статистика качества и происхождение.
- http://localhost:8000/docs — описание доступных технических API.

При ошибке загрузки оба рабочих endpoint возвращают HTTP 503; подробности с файлом, строкой, id и полем доступны в журнале сервера и CLI. Это не бизнес-исход пустого подбора. POST /api/recommendations возвращает до трёх карточек с проверяемыми объяснениями; CLI ниже сохраняет внутреннюю диагностику этапа 4. CORS и прокси не нужны прототипу: запросы из браузера к серверу пока не отправляются.

Проверка каталога и тесты, из `backend/`:

```bash
.venv/bin/python -m app.cli
.venv/bin/python -m pytest -q
```

`app.cli` возвращает JSON-отчёт, при ошибке — exit code 1 и JSON-диагностику в stderr. Пример текущего отчёта: [catalog-report.json](docs/catalog-report.json). [Правила импорта и происхождения](docs/catalog.md).

## CSV, JSONL и отдельные фикстуры

По умолчанию сервер читает только `hackathon dataset anonymized .csv` из корня репозитория. Путь `CATALOG_PATH` задаётся относительно корня проекта или абсолютным путём. Дополнительные источники автоматически не объединяются.

Из `backend/` можно воспроизводимо создать новый производный файл:

```bash
.venv/bin/python -m app.cli --export data/derived/new-catalog.jsonl
.venv/bin/python -m app.cli data/derived/new-catalog.jsonl
```

Вместе с JSONL создаётся `.meta.json` с происхождением каждого профиля. Переносите оба файла вместе. Существующие файлы экспорт не перезаписывает. В репозитории уже сохранён проверенный экспорт `data/derived/catalog.jsonl`; он является другой формой исходного CSV, а не дополнительным набором.

Запуск сервера с JSONL из корня:

```bash
CATALOG_PATH=data/derived/catalog.jsonl backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Изолированная проверка демофикстур, из `backend/`:

```bash
.venv/bin/python -m app.cli backend/tests/fixtures/catalog_valid.jsonl --origin demo
```

Отдельный сервер с тестовым каталогом, из корня:

```bash
CATALOG_PATH=backend/tests/fixtures/catalog_valid.jsonl CATALOG_ORIGIN=demo backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8001
```

Такой каталог содержит два вымышленных профиля и не смешивается с оригиналом. Это проверка загрузки данных, не полноценное демо рекомендаций. Фронтенд ещё не подключён к этому режиму. Для отдельно добавленных командой записей есть явное происхождение `team`; оно требует `synthetic: true`. Флаг `synthetic` сам по себе не определяет происхождение.

Сведения о стадиях, фактических проверках и ограничениях: [progress.md](docs/progress.md).


## Подбор: этап 4

Из `backend/`:

```bash
.venv/bin/python -m app.match_cli --query docs/queries/corporate-host.json
```

Для Алматы, ведущего, корпоратива 30.09.2026 с бюджетом 1 000 000 ₸ проходят шесть профилей; первые три — HK-88430, HK-44923, HK-35215. Файл `corporate-host-next-date.json` меняет дату на 01.10.2026: остаются HK-88430 и HK-44923, Кики занят.

[Правила и все семь сценариев](docs/matching.md), [вычисленный отчёт](docs/matching-report.json).

Условия обязательны: город и категория, доступность на дату, формат, бюджет, язык и длительность при их указании. Затем сортировка по начальной цене и каноническому id; вывод до трёх профилей. Счётчики основных причин не учитывают одного исключённого кандидата дважды. Результаты MATCHED, CATEGORY_UNAVAILABLE, NO_MATCHES отделены от ошибок валидации и загрузки.

Подбор не использует AI и не оценивает качество подрядчика по цене. CLI этапа 4 показывает диагностику; публичный API этапа 5 дополнительно формирует объяснения. Подключение к сайту остаётся этапом 6. Примеры CLI — диагностические результаты, а не готовый контракт браузерного API.


## Объяснения и API: этап 5

При запущенном сервере, из корня проекта:

```bash
curl -X POST http://localhost:8000/api/recommendations \
  -H 'Content-Type: application/json' \
  --data-binary @docs/queries/corporate-host.json
```

[Контракт API, сериализация и правила объяснений](docs/api.md). Реальные сохранённые ответы: [основной запрос](docs/api-examples/corporate-host.json), [пустая выдача](docs/api-examples/no-matches.json), [отсутствующая категория](docs/api-examples/no-category.json), [минимальная длительность фотобудки](docs/api-examples/minimum-duration.json).

Объяснение объединяет подтверждённые условия запроса с точной атрибутированной цитатой. Для исходного набора вручную размечен 61 содержательный фрагмент; ещё 5 описаний отмечены как недостаточные. Хэш описания и контекст полей защищают от использования устаревшей разметки. При неизвестном/изменённом профиле остаются структурированные факты и понятное ограничение. Внешняя модель не вызывается.

Валидные бизнес-исходы возвращают 200, ошибки запроса — 422, незагруженный каталог — 503, внутренний сбой — 500. Тексты ошибок не содержат исходный запрос или трассировку.

Из `backend/` можно обновить схему, типы TypeScript и примеры:

```bash
.venv/bin/python -m app.export_contract
.venv/bin/python -m app.export_examples
```

Фронтенд получает типы из OpenAPI и готовый fetch-клиент с AbortSignal. Он ещё не вызывается страницей; показанные на сайте карточки по-прежнему демонстрационные.
