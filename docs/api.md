# Объяснения и API: этап 5

## Контракт

Сервер на `http://localhost:8000`, интерактивная схема — `/docs`, OpenAPI — `/openapi.json`. Сохранённая схема: [openapi.json](openapi.json). Типы фронтенда генерируются из неё, а не поддерживаются отдельно вручную.

| Метод / путь | Назначение | Успешный ответ |
|---|---|---|
| GET /health | Готовность реально загруженного каталога | status=ready, profile_count, catalog_version |
| GET /api/catalog/meta | Справочники, календарь, происхождение, версия и качество | CatalogMetadata |
| POST /api/recommendations | Подбор с объяснениями и доказательствами | RecommendationResponse |

Из корня проекта, при запущенном сервере:

```bash
curl -X POST http://localhost:8000/api/recommendations \
  -H 'Content-Type: application/json' \
  --data-binary @docs/queries/corporate-host.json
```

Запрос:

```json
{
  "city": "Алматы",
  "category": "Ведущий",
  "event_date": "2026-09-30",
  "event_format": "корпоратив",
  "budget_kzt": 1000000,
  "duration_hours": null,
  "language": null
}
```

Пять обязательных полей, два необязательных. Все правила этапа 4 сохранены. Текст сравнивается после нормализации; неизвестные значения справочников отклоняются. Непустые числовые строки не принимаются вместо чисел. Пустые необязательные значения и null снимают ограничение.

## Сериализация

- Бюджет и цена — JSON integer в целых тенге. В HTTP API бюджет ограничен 9 007 199 254 740 991 ₸ (Number.MAX_SAFE_INTEGER), поэтому допустимые карточки также укладываются в точный целочисленный диапазон браузера. Это ограничение передачи в браузер, внутренний Python-подбор не изменён. Не округляются до тысяч, не конвертируются во float.
- Входная длительность — положительный конечный JSON number; строка допустима только пустая/из пробелов для отсутствующего условия.
- Выходная длительность в `query.duration_hours`, `cards[].max_hours` и соответствующих значениях evidence — точная строка Decimal либо null. Например, `"125e-2"` означает 1.25 часа, `"1e1"` — 10 часов. Это явно разные схемы ввода и вывода; интерфейс не должен отправлять строковую длительность из ответа без преобразования. Для показа человеку есть `duration_text`.
- Дата — ISO `YYYY-MM-DD`, без времени и часового пояса.
- Списки — JSON arrays, флаги — boolean, отсутствующие значения — null. TS-типы отмечают поля с серверными значениями по умолчанию как необязательные; сервер сейчас сериализует их явно.

Точная выходная запись Decimal выбрана для сохранения данных расширенного каталога без потери точности или переполнения при преобразовании во float. Типы различаются по именам `RecommendationRequest` и `RecommendationQuery`. Регулярные ограничения строк проверяются сервером; TypeScript не выражает регулярное ограничение пустой строки.

## Ответ

`status` — MATCHED, CATEGORY_UNAVAILABLE или NO_MATCHES; все три возвращают HTTP 200. Поля `message`, `query`, `catalog_version`, `ranking_version`, `explanation_version`, `counts`, `rejections`, `cards`, `warnings` обязательны. Для будущего сравнения дат также возвращаются `eligible_ids` и `exclusions` с полным набором причин и одной основной причиной. Советов по ослаблению условий пока нет, поле suggestions не добавлено.

Карточка содержит id, имя, выбранную категорию (она также первая в categories), город, исходную цену и готовую подпись «от … ₸», дату и подпись доступности по календарю набора, языки, длительность, объяснение, evidence, происхождение и пометки качества. Полный description в карточку не копируется.

Одинаковые запрос, каталог и версия объяснений дают одинаковые карточки и порядок. Генерация объяснений не изменяет фильтры и сортировку.

## Откуда берутся объяснения

В `backend/app/data/profile_facts.json` вручную размечен предоставленный набор из 66 профилей: 61 точный содержательный фрагмент и 5 случаев недостаточных описаний. Разметка не добавляет новых профилей. Это ручной анализ данных, не вызов NVIDIA и не обещание автоматического понимания любых будущих описаний.

Для каждого фрагмента сохранены SHA-256 полного исходного описания и контекст полей, на которые опираются предупреждения. В момент построения карточки проверяются хэш, контекст и вхождение цитаты в оригинал. При изменении описания или контекста, неизвестном профиле либо отсутствии разметки цитата не используется: остаются проверяемые структурированные сведения и DESCRIPTION_LIMITED. Кэш разметки локальный для процесса; после её изменения перезапустите сервер. explanation_version включает SHA-256 файла разметки.

Короткие фрагменты выбирались с сохранением отрицаний, чисел и единиц; рекламные рейтинги, превосходные степени и медицинские обещания исключались. Для части площадок используется точное словосочетание, а не полное рекламное предложение. Такой фрагмент не выдаётся за весь текст описания.

Объяснение состоит из двух предложений: атрибутированный фрагмент описания (либо доступные структурированные отличия) и сопоставление начальной цены/бюджета, формата и даты. Различия не объявляются предполагаемыми предпочтениями клиента. При одинаковых фрагментах у нескольких карточек даётся явная пометка об ограниченности различий.

Исходная цитата хранится в `evidence.quote` неизменной. Для интерфейса предназначены `evidence.text`, labels, warnings.message и остальные подготовленные строки. При удалении декоративного оформления выставляется `display_is_cleaned`; очищенный фрагмент не называется дословным оригиналом. Функция очистки сохраняет отрицания, числа, знаки сравнения и символ тенге. React должен отображать эти строки как текст, не как HTML.

Каждый structured evidence содержит code, field, profile_value, requested_value и понятное сравнение в text. Для даты profile_value — исходный список занятых дат, поэтому отсутствие даты можно перепроверить. Все исходные поля остаются доступны в каталоге, пользовательский интерфейс не должен печатать raw evidence как JSON.

## Ограничения источников

Предупреждения сопровождаются точной цитатой-основанием: конференции в описании Кики вне списка форматов, дополнительная география Сацуки, репертуар Каору, другое название дуэта, минимальная аренда 3 часа, минимальные заказы 15/20 изделий, ограничение стиля Крилина. Эти условия не превращаются в скрытые фильтры.

Например, запрос фотобудки на 2 часа проверяет только структурированный максимум. Карточка дополнительно предупреждает об указанном в описании минимуме 3 часа и необходимости уточнения. Начальная цена не становится ценой за штуку или подтверждённой итоговой стоимостью.

Синтетичность, дополненные город/цена и origin отмечены независимо. Исходный synthetic=false не называется проверенным подрядчиком. Доступность всегда ограничена календарём датасета.

## Ошибки

| HTTP | code | Значение |
|---|---|---|
| 422 | INVALID_QUERY | Неверные параметры, неизвестный справочник или повреждённый JSON |
| 503 | CATALOG_LOAD_FAILED | Каталог не загружен |
| 500 | INTERNAL_ERROR | Неожиданный сбой приложения |

Единая форма: `{ "code": "…", "message": "…", "issues": [{ "field": "…", "message": "…" }] }`. Ошибки не раскрывают значения отклонённого запроса, трассировки и внутренние пути. Исключение при ответе не маскируется пустой подборкой.

Используются [модели ответов FastAPI](https://fastapi.tiangolo.com/tutorial/response-model/) и [обработчики ошибок](https://fastapi.tiangolo.com/tutorial/handling-errors/). Обработчик API проверяет ответ по публичной схеме перед сериализацией.

## Генерация и интеграция

Из `backend/`:

```bash
.venv/bin/python -m app.export_contract
.venv/bin/python -m app.export_examples
```

Первая команда обновляет OpenAPI и `frontend/src/lib/api/generated.ts`, вторая сохраняет реальные ответы в `docs/api-examples/`. Генератор типов поддерживает используемые схемой объекты, массивы, enum, ссылки, объединения и nullable; при неизвестной конструкции останавливается с ошибкой.

`frontend/src/lib/api/client.ts` подключён к странице: содержит типизированный fetch-клиент, ошибки, AbortSignal и проверку структуры успешного ответа через Zod. Vite проксирует `/api` на локальный сервер. Справочники, реальные карточки, диагностика и предупреждения приходят из API. Новый запрос убирает старую выдачу и отменяет предыдущий запрос; счётчик запросов дополнительно исключает применение запоздалого ответа. Таймаут запроса — 12 секунд. Изменённые поля до отправки явно отличаются от подписанных условий прежней выдачи.

NVIDIA не вызывается и не требуется. Интеграционные браузерные проверки относятся к этапу 6; общая проверка демонстрации и замер полного пользовательского пути — к этапу 7.
