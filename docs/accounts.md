# Аккаунты AI-ANA

Добавлены регистрация по email и паролю, вход, выход и редактирование имени и города. Окно открывается из шапки. После входа кнопка меняется на «Профиль». Подбор остаётся доступным гостям; существующие параметры и результаты сохраняются при открытии и закрытии окна аккаунта.

## Хранение и настройки

SQLite создаётся автоматически при запуске API. Исходный CSV подрядчиков не меняется. База содержит аккаунты, сессии и счётчики попыток входа; она не включается в репозиторий. Новых Python/npm-зависимостей не требуется.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| AUTH_DB_PATH | data/auth/accounts.sqlite3 | Путь относительно корня проекта либо абсолютный |
| AUTH_COOKIE_SECURE | false | true для HTTPS, чтобы cookie отправлялась только защищённым соединением |
| AUTH_ALLOWED_ORIGINS | localhost и 127.0.0.1 на локальных портах 5173/4173/5174/4174/8000 | Разрешённые origin, разделённые запятой; на хостинге задать точный публичный адрес сайта |

Задавайте переменные в окружении процесса (файл `.env.example` служит примером и автоматически не загружается). Для будущего Docker-развёртывания каталог базы нужно хранить в отдельном volume. Для резервного копирования работающей базы используйте SQLite backup API: база работает в режиме WAL, копирование только основного файла во время записи может потерять последние изменения.

## API

Все ответы аккаунтов имеют `Cache-Control: no-store`. Успешный ответ: `{user, csrf_token}`; у гостя оба поля null. Пользователь: `id`, `email`, `name`, `city`, `created_at`. Изменяющие запросы требуют JSON и заголовок `X-Requested-With: AI-ANA`. Если передан Origin, он должен входить в разрешённый список.

| Метод и путь | Тело | Результат |
|---|---|---|
| GET /api/auth/me | — | Текущий пользователь либо гость |
| POST /api/auth/register | email, password, name, city (необязательно) | 201, аккаунт и новая сессия |
| POST /api/auth/login | email, password | 200, новая сессия |
| PATCH /api/auth/profile | name, city | 200, сохранённый профиль; нужен X-CSRF-Token |
| POST /api/auth/logout | {} | 200, отзыв сессии; для живой сессии нужен X-CSRF-Token |

CSRF-токен берётся из последнего успешного ответа `/me`, входа или регистрации. Сессия хранится в HttpOnly cookie `ai_ana_session` с `SameSite=Lax`, путём `/api/auth` и сроком 7 дней. Сам токен сессии не возвращается в JSON и не записывается в localStorage. В базе хранится только его SHA-256. Вход и регистрация отзывают предыдущую сессию этого браузера. Выход завершает текущую сессию, другие устройства остаются авторизованы.

Пароли хэшируются scrypt с отдельной случайной солью (`N=2^17`, `r=8`, `p=1`). Лимит параллельных вычислений — два. Подход выбран по [рекомендациям OWASP по хранению паролей](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html); защита изменяющих запросов учитывает [рекомендации OWASP по CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

Ограничения ввода: имя 2–80 символов, город до 80, email до 254 (обычный ASCII-формат, приводится к нижнему регистру), пароль при регистрации 15–128 символов. Пробелы в пароле сохраняются. Email не подтверждается письмом. Ответ неверного входа одинаков для неизвестного email и неверного пароля; регистрация существующего email возвращает 409.

Коды ошибок: 401 — неверные данные входа/истекшая сессия; 403 — защита запроса; 409 — регистрация недоступна для этого email; 422 — поля формы; 429 — лимит попыток. Лимиты сохраняются в SQLite: регистрация 10 запросов с IP за 15 минут; вход 30 с IP и 10 на email за 15 минут. При развёртывании за прокси следует правильно настроить доверенные proxy headers, иначе посетители будут делить лимит адреса прокси. Текущий вариант предназначен для локального запуска и небольшой нагрузки.

## Границы версии

Пока нет подтверждения email, восстановления/смены пароля, входа через Google, удаления аккаунта, истории подборов и синхронизации состояния между открытыми вкладками. Email в профиле доступен только для чтения. Сохранённый город не влияет на текущие условия подбора.

Проверки авторизации используют отдельные временные базы; браузерные тесты не создают аккаунты в пользовательской базе. Покрыты полный жизненный цикл, сохранение после перезапуска, отзыв и истечение сессии, изоляция пользователей, CSRF, ограничения ввода, хэширование и лимиты попыток.

Проверено 23.09.2026: сборка успешна, **266 серверных тестов прошли (11.24 s), 19 браузерных тестов прошли (46.7 s)**. Прежние сценарии подбора также проходят. Остаётся предупреждение Starlette/httpx об устаревшем тестовом адаптере; оно не связано с аккаунтами.
