## Принятый план

Стек сохраняется: React + TypeScript + Vite, Tailwind CSS, shadcn/ui, React Hook Form + Zod; Python + FastAPI + Pydantic; pytest и Playwright. Версии пакетов фиксировать после проверки совместимости на соответствующем этапе.

1. Аудит и план — выполнены, результаты в этом документе.
2. Дизайн и каркас фронтенда — светлый вариант А, форма, явно демонстрационные карточки, настройки акцента, логотип. Проверить ширины 390/768/1440 px и отсутствие горизонтальной прокрутки на 320 px.
3. Каталог и валидация — сервер, единая модель, CSV/JSONL, строгая диагностика повреждённых данных и отдельные тестовые фикстуры.
4. Подбор и диагностика — обязательные фильтры, сортировка по начальной цене и id, три исхода, все причины и основные счётчики.
5. Объяснения и API — индивидуальные подтверждаемые объяснения, evidence, контракты и интеграционные проверки.
6. Полный интерфейс — API, состояния, смена даты, отмена устаревших ответов, сохранность оформления и формы.
7. Проверка и демонстрация — браузер, снимки, сценарии, детерминизм после перезапуска, замеры времени.
8. Документация и сдача — README, сценарий защиты, команды запуска и повторная проверка по документации.

Планируемая структура: `frontend/` (компоненты, форма, оформление, API-клиент, бренд), `backend/app/` (модели, загрузчики, подбор, объяснения, API), `backend/tests/`, `tests/e2e/`, `docs/`. Папки создавать по мере выполнения разрешённых этапов. Исходный CSV пока остаётся на месте, будущий загрузчик получает настраиваемый путь относительно проекта. Демонстрационные данные хранить отдельно; производный JSONL не загружать одновременно с исходным CSV.

## Допущения и ограничения

- Календарное окно фиксировано: 23.09.2026–31.12.2026. Оно не сдвигается вместе с системным временем.
- Деньги в ядре — целые тенге; длительность может быть дробной. Пустое max_hours означает отсутствие привязки к длительности присутствия.
- Структурированные поля определяют фильтры; описание служит источником проверяемых особенностей и предупреждений. Конфликты из разделов 9 и 21 включить в дальнейшие тесты.
- DOCX не требует красивого UI, но пользовательский Markdown добавляет его как обязательный объём. Это дополнение, а не противоречие. Требование различимых объяснений проверять вручную; при недостатке различий в источнике честно показывать ограничение.
- NVIDIA только предусмотрен архитектурой: не реализован, ключ, модели и доступность не проверены. Ядро работает без AI-сервиса; интеграция возможна после обязательных этапов по отдельному разрешению.
- Приложения пока нет: запуск, тесты pytest/Playwright, визуальная проверка интерфейса и время ответа ещё не проверялись.
- Каждый следующий этап требует отдельного разрешения по разделу 19 Markdown.
